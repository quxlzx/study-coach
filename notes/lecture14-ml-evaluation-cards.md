Overfitting:: What is overfitting? :: The model learns the training data too closely, including noise and random patterns; it performs very well on training data but poorly on new, unseen data
Overfitting:: Why does overfitting happen? :: The model memorizes instead of learning general patterns; drivers are noisy data, excessive model complexity, and insufficient data size
Overfitting:: What are the 3 ways to reduce overfitting? :: 1) Collect diverse, representative data (train with sufficient data), 2) evaluate with cross-validation, 3) reduce complexity or regularize (penalize parameters so they are less noise-sensitive)
Underfitting:: What is underfitting? :: The model is too simple to capture important patterns and performs poorly on BOTH training and unseen data; example: admissions decisions based only on GPA
Underfitting:: What causes underfitting and how do you fix it? :: Too-simple model, missed features, unreliable predictions; fix by increasing complexity: more layers/neurons in a neural net, higher polynomial degree
Bias:: What is bias in the bias-variance tradeoff? :: Error from approximating a complex real-world problem with a simplified model; it quantifies how much predicted values differ from actual (expected) values; high bias = oversimplified model that underfits
Variance:: What is variance in the bias-variance tradeoff? :: Error from being overly sensitive to fluctuations in the training set; it is the spread of predictions for a given point across different training subsets; high variance = overly complex model, great training score, poor test error
Bias-Variance:: What is the basic ML recipe for diagnosing bias vs variance? :: If training performance is bad (HIGH BIAS): bigger network, train longer. If test/validation performance is bad (HIGH VARIANCE): get more data, apply regularization. Neither: done
Bias-Variance:: What is the optimal (Bayes) error? :: The irreducible error floor; assuming 0% human error, the optimal Bayes error is nearly 0%; the ideal model has low bias AND low variance
Data Splitting:: Why do we hide data from the algorithm (holdout)? :: The real goal is generalization: a useful model must predict on new cases (e.g. bank lending beyond past applicants), so we train on one split and test on unseen data
Data Splitting:: Why have a validation set instead of tuning on the test set? :: Trying many settings on the test set biases results; choose the best model using validation performance and reserve the test set until model development is complete
Cross-Validation:: Why is a single train/validation split not enough, and what does cross-validation do? :: One partition may over- or underrepresent groups and create distribution differences; CV splits training data into several folds, trains on some and validates on another, repeating and summarizing performance
K-Fold CV:: How does K-Fold cross-validation work? :: Split data into K equal subsets; iteratively train on K-1 folds and validate on the held-out fold; each fold validates once (K = 5 or 10 typical); average the K validation scores and keep the test set separate
K-Fold CV:: What is Stratified K-Fold and when is it recommended? :: A K-Fold variant that preserves approximately the same class proportions in every fold as in the full dataset; recommended for classification, especially imbalanced datasets
LOOCV:: What is Leave-One-Out Cross-Validation and its tradeoff? :: The extreme K-Fold where K = N: train on N-1, validate on the single held-out point, repeat N times and average; uses nearly all data with high precision but is computationally expensive and slow on large datasets
Class Imbalance:: What is the accuracy trap under class imbalance? :: If 90% of examples are negative, always guessing "negative" yields 90% accuracy while detecting 0% of positives; imbalance (fraud, disease, purchases: rare positives among many negatives) changes how accuracy should be read
Confusion Matrix:: Name the 4 cells of the confusion matrix :: TP = caught a real positive, FP = false alarm (predicted +, actually -), FN = missed a positive (predicted -, actually +), TN = all clear; first letter = truth, second = the model's claim
Precision:: Give the precision formula and when to use precision :: Precision = TP / (TP + FP): of all predicted positives, how many were truly positive; use when false alarms are costly (minimize FP), e.g. Google hiring only engineers who will succeed; 1.0 = never wrong when predicting positive
Recall:: Give the recall formula and when to use recall :: Recall = TP / (TP + FN): of all actual positives, how many did we catch; use when missed cases are costly (minimize FN), e.g. cancer screening, fraud, a contagious super plague; 1.0 = never misses the target class
Precision vs Recall:: Which metric matters for: cancer testing, fraud alerts, loans? :: Cancer: recall (don't miss cases; further tests can follow). Fraud alerts: recall (better to deny good transactions than pay fraud losses). Loans: precision (only lend to people who will pay back). Legal system: depends
F1 Score:: Give the F1 formula and when it is useful :: F1 = 2PR / (P + R); ranges 0 to 1 and is high only when BOTH precision and recall are strong; useful when false alarms and missed positives both matter (flagging harmful content) and for imbalanced datasets
Precision vs Recall:: What is the precision-recall tradeoff? :: Increasing precision typically decreases recall and vice versa, so both cannot be maximized at once; the F1 score balances them in a single metric
Log Loss:: Why is accuracy not enough, and what does log loss measure? :: Two equally wrong predictions can differ in confidence: a 99% confident wrong call should be penalized more than a 60% one; log loss grades predicted probabilities against true classes - lower is better, closer to 0 is ideal
Log Loss:: Does log loss apply beyond binary classification? :: Yes - for multiclass with N data points and M classes, using actual outcome Xij and predicted probability Pij per point/class
